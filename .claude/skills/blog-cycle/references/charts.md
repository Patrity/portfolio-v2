# Phase 2 — Charts

Invoke the `dataviz` skill BEFORE writing any chart code — it owns form
selection, the color method, and the palette validator. This file records how
its method is instantiated for this site.

## Site-specific instantiation

- **Static SVG figures**, generated by a Node script (compute geometry, don't
  hand-place), written to `public/images/blog/<slug>/*.svg`, embedded with
  plain markdown images. Start from `scripts/chart-template.mjs` (session-tested:
  card chrome, bar helper with 4px rounded data-end, text helper).
- **Self-contained dark card surface** (`#1a1a19`, rounded, hairline border) so
  charts read as intentional on both site themes — an `<img>` can't see the
  site's theme toggle.
- **Direct-label every value.** No hover layer exists in a static image. The
  post's tables/prose serve as the accessible table-view twin.
- **Palette:** dataviz dark steps — blue `#3987e5` slot 1, aqua `#199e70`
  slot 2, de-emphasis gray `#898781`. Run the dataviz validator on the exact
  slots used (`--mode dark --surface "#1a1a19"`); don't trust memory.
- **Honest footnotes.** Every chart with a methodology caveat (marginal cost,
  estimated rate, excluded data) states it in a muted footnote. Credibility is
  the brand.

## Workflow

1. Pick 2–4 charts that each earn their place (one hero comparison, one
   composition/attribution, one insight). A number that isn't a comparison is
   a stat tile in prose, not a chart.
2. Generate → render to PNG (`rsvg-convert -w 1600`) → **Read the PNG and look
   at it** (label collisions, spacing bugs) → fix → re-render.
3. Produce PNG copies alongside the SVGs — cross-posts (dev.to) need them.
   Both go in `public/images/blog/<slug>/`.
4. Reference in the post with meaningful alt text carrying the actual numbers.
